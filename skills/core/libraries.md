## Page-weight budget

A typical report (React, one chart library, Mermaid) stays under 1.5 MB of decompressed JS. elkjs, p5, three and GSAP come on top only for pages that need them. Prefer Mermaid over React Flow + elkjs unless the diagram must be interactive.

## Library CSS

Artifact pages cannot fetch from a CDN, and a `<link>` may only load Google Fonts from outside the page. Library stylesheets ship in `vendor/`:

| File | For |
|---|---|
| `vendor/carbon-charts.css` | @carbon/charts-react 1.27.20 |
| `vendor/xyflow.css` | @xyflow/react 12.12.0 |

1. Copy the file into the working or scratchpad directory next to the page (the Artifact tool only publishes files from there).
2. Publish it with the page: `files: {"carbon-charts.css": "<path to the copy>"}`.
3. Link it: `<link rel="stylesheet" href="./carbon-charts.css">`.

For local HTML files, link the vendor file by relative path instead.

## Mermaid

Paste `mermaid.css` (this folder) into the page's `<style>`, after the look's tokens. It restyles whatever Mermaid renders (nodes, labels, edges, arrowheads) with the `--pa-*` tokens, so a single diagram block follows the page theme. The artifact viewer renders Mermaid in its default theme and ignores `%%{init}%%` colours, which is why colour is done in CSS. The file also keeps unrendered source from widening the page.

**Artifacts** render `<pre class="mermaid">` natively; do not load the library. A diagram that would be a long chain wraps into rows:

```html
<figure>
<pre class="mermaid">
flowchart TB
  accTitle: The four layers of the industry
  accDescr: Parts supply robot brains, which supply robot makers, which supply single-job robots.
  subgraph lower [" "]
    direction LR
    P[Picks and shovels] --> B[Robot brains]
  end
  subgraph upper [" "]
    direction LR
    M[Robot makers] --> S[Single-job robots]
  end
  lower --> upper
  class S focus
</pre>
<figcaption>Each layer supplies the next.</figcaption>
</figure>
```

Link the rows subgraph to subgraph (`lower --> upper`). Mermaid ignores a subgraph's `direction` as soon as any node inside it links to a node outside, and the rows collapse back into one tall column.

A hub and spoke (star) puts one node at the centre: `flowchart LR` with `Hub --- A`, `Hub --- B`, and so on.

**Local HTML** loads Mermaid and re-renders on theme change:

```js
import mermaid from "https://cdn.jsdelivr.net/npm/mermaid@12.0.0/+esm";
const token = n => getComputedStyle(document.documentElement).getPropertyValue(n).trim();
async function drawDiagrams() {
  mermaid.initialize({
    startOnLoad: false, theme: "base",
    flowchart: { nodeSpacing: 32, rankSpacing: 48, padding: 16 },
    themeVariables: {
      fontFamily: token("--pa-font-sans"), fontSize: "16px",
      background: token("--pa-bg"), primaryColor: token("--pa-surface"),
      primaryTextColor: token("--pa-text"), primaryBorderColor: token("--pa-border"),
      lineColor: token("--pa-text-2"), secondaryColor: token("--pa-surface"), tertiaryColor: token("--pa-bg"),
    },
  });
  for (const el of document.querySelectorAll("pre.mermaid")) {
    el.dataset.src ??= el.textContent;
    const { svg } = await mermaid.render(`m${Math.random().toString(36).slice(2)}`, el.dataset.src);
    el.innerHTML = svg;
  }
}
await drawDiagrams();
new MutationObserver(drawDiagrams).observe(document.documentElement, { attributes: true, attributeFilter: ["data-theme"] });
matchMedia("(prefers-color-scheme: dark)").addEventListener("change", drawDiagrams);
```

`themeVariables` apply only with `theme: "base"` and need resolved colours, which is why they are read from computed style.

## Charts

- Carbon Charts: `import { SimpleBarChart } from "https://cdn.jsdelivr.net/npm/@carbon/charts-react@1.27.20/+esm"`, options `{ theme: dark ? "g100" : "white", legend: { alignment: "left" }, toolbar: { enabled: false } }`, plus `vendor/carbon-charts.css`. Re-render when `data-theme` or `prefers-color-scheme` changes, with the same observer as Mermaid.
- Recharts: colours from `--pa-cat-*`, axis and grid from `--pa-text-2` and `--pa-border`, `isAnimationActive={false}` under reduced motion, direct `<LabelList>` labels instead of `<Legend>`.
- Every chart's data is also written into the HTML as a `<table>` (see accessibility.md), so the page still reads if the CDN fails.

## Motion, explorables, 3D

Paste `motion.js` (core) into a plain `<script>` first. It turns the look's `--pa-ease*` and `--pa-dur-*` tokens into what GSAP and anime.js take: `paEase(name)` returns an easing function, `paDur(name)` returns seconds, `paReduced()` reports reduced motion. Both libraries accept an easing function; neither reads a CSS `cubic-bezier()` or `linear()` string.

- GSAP 3.15.0 (free for all use since 30 April 2025, ScrollTrigger included): `import { gsap } from "https://cdn.jsdelivr.net/npm/gsap@3.15.0/+esm"` and `import { ScrollTrigger } from "https://cdn.jsdelivr.net/npm/gsap@3.15.0/ScrollTrigger/+esm"`, then `gsap.registerPlugin(ScrollTrigger)`. Durations are seconds.
- anime.js 4.5.0: `import { animate, stagger, createTimeline } from "https://cdn.jsdelivr.net/npm/animejs@4.5.0/+esm"`. Durations are milliseconds: `paDur(...) * 1000`. Version 4 removed string eases from the core; pass `paEase(...)`.

State change with anime.js, a bar moving to its new value when a filter changes:

```js
import { animate } from "https://cdn.jsdelivr.net/npm/animejs@4.5.0/+esm";
function setBar(el, pct) {
  if (paReduced()) { el.style.width = pct + "%"; return; }
  animate(el, { width: pct + "%", duration: paDur("--pa-dur-mid") * 1000, ease: paEase("--pa-ease") });
}
```

Load sequence for the opening figure with GSAP. The figure is drawn complete in HTML; the timeline starts from that state with `from` tweens set in the same frame, so a failed script leaves the finished figure:

```js
import { gsap } from "https://cdn.jsdelivr.net/npm/gsap@3.15.0/+esm";
if (!paReduced()) {
  // Brief: bars grow left to right in rank order so the leader reads first; 0.08s stagger; labels follow 0.15s after their bar.
  const tl = gsap.timeline({ defaults: { ease: paEase("--pa-ease-enter"), duration: paDur("--pa-dur-slow") } });
  tl.from(".bar", { scaleX: 0, transformOrigin: "left center", stagger: 0.08 })
    .from(".bar-value", { opacity: 0, stagger: 0.08, duration: paDur("--pa-dur-mid") }, 0.15);
}
```

Scroll-linked figure: the figure stays in place with CSS `position: sticky` (in the rail from 1440px, or above the text on smaller screens), and each section that scrolls past sets its state. ScrollTrigger only reports which section is active; the state change itself is a short tween:

```js
import { gsap } from "https://cdn.jsdelivr.net/npm/gsap@3.15.0/+esm";
import { ScrollTrigger } from "https://cdn.jsdelivr.net/npm/gsap@3.15.0/ScrollTrigger/+esm";
gsap.registerPlugin(ScrollTrigger);
function show(state) {  // draws one state; also called on load with the first state
  for (const bar of figure.querySelectorAll(".bar")) {
    const to = { width: state.values[bar.dataset.key] + "%" };
    paReduced() ? gsap.set(bar, to) : gsap.to(bar, { ...to, duration: paDur("--pa-dur-slow"), ease: paEase("--pa-ease"), overwrite: true });
  }
}
for (const section of document.querySelectorAll("[data-state]")) {
  ScrollTrigger.create({ trigger: section, start: "top 60%", end: "bottom 60%",
    onToggle: self => self.isActive && show(STATES[section.dataset.state]) });
}
```

Every state's numbers also appear in its section's text or a table, so the page reads without the figure moving.
- p5.js: `import p5 from "https://cdn.jsdelivr.net/npm/p5@2.3.4/+esm"` in instance mode (`new p5(sketch, el)`), paused under reduced motion, with a range input for every parameter the text discusses.
- three.js: `import * as THREE from "https://cdn.jsdelivr.net/npm/three@0.186.1/+esm"`. Scene background from `--pa-bg`, never transparent over text. Provide a still image or a text description for print and reduced motion.
