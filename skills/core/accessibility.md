# Accessibility and print

## Keyboard and focus
- Every control is a real `<button>`, `<a>`, `<input>` or `<summary>`. No clickable `div`.
- Focus ring on everything focusable: `:focus-visible { outline: 2px solid var(--pa-focus); outline-offset: 2px; }`
- Tab order follows reading order. No positive `tabindex`.

## Charts and diagrams
Structure for every chart:

```html
<figure>
  <div role="img" aria-label="One sentence stating what the chart shows">…chart…</div>
  <figcaption>What to notice.</figcaption>
  <details><summary>Data</summary><table>…every plotted value…</table></details>
</figure>
```

The table is written in the HTML, not generated by the chart library, so it survives a CDN failure. Every Mermaid source begins with `accTitle: …` and `accDescr: …`.

## Contrast
Body text 4.5:1; large text, chart marks and focus rings 3:1; in both themes. The look's tokens already pass. Do not introduce other colours.

## Reduced motion

Pages play full motion by default; the owner chose this over following the operating system's `prefers-reduced-motion`. Every page with motion pastes `motion.js` and calls `paMotionInit()`, which adds a floating "Reduce motion" button (styled in `layout.css`). Pressing it sets `data-motion="reduce"` on the root, which `layout.css` uses to switch off every CSS animation and transition, remembers the choice in `localStorage`, and fires a `pa-motion` event.

`motion.js` applies a saved choice as it loads, so scripts that run before `paMotionInit()` still see it. Scripts check `paReduced()` before animating and pass every animation they start through `paTrack()`: `paTrack(gsap.timeline(…))`, `paTrack(animate(…))`. Pressing the button then finishes them all: GSAP loops stop at their end, scrubbed tweens lose their ScrollTrigger, and anime.js animations complete. Scroll-linked figures that set state with `gsap.set` under `paReduced()` need nothing more.

When reduced: pass `isAnimationActive={false}` to Recharts, skip GSAP and anime.js timelines, pause p5 loops, and render three.js scenes as one still frame.

## Print
The artifact viewer cannot open a print dialog, so never add a Print button. Readers still print from the browser, and local HTML prints normally:

```css
@media print {
  :root { color-scheme: light; }
  details::details-content { content-visibility: visible; display: contents; }
  button, input, [data-print="hide"] { display: none !important; }
  figure, table { break-inside: avoid; }
}
```

```js
addEventListener("beforeprint", () => document.querySelectorAll("details").forEach(d => (d.open = true)));
```

A closed `<details>` hides its content from print even when the CSS unhides its children, so both lines are needed. Keep the `<summary>` visible: it labels the section.

Set the light theme's token values inside `@media print` as well, so a dark-mode reader prints a light page.
